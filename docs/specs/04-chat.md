# 仕様 04：ルームチャットとクイックリアクション

ブランチ：`feature/chat`
前提：CLAUDE.md、仕様01〜03（members / role / settings.spectatorSeesAll / viewFor / ルールパネル / ボトムシート）。
**最初に現状のコードを読み、名前が違う箇所は実際のコードに合わせること。読み替えた箇所は報告に書く。**

## 1. 要件
- ルームごとのチャット。ロビー・ゲーム中・結果画面のどこでも使える
- 文字のメッセージに加えて、ワンタップで送れる **クイックリアクション**（定型文）
- 観戦機能と矛盾させない：観戦者に手札が見えている設定のとき、観戦者がチャットで手札をばらせないようにする

## 2. 決めごと
| 項目 | 決定 |
|---|---|
| 保存 | サーバーのメモリにルームごと最新 **100件**。ルームが消えたら消える（DBなし） |
| 文字数 | 1件 **140文字** まで。前後の空白を削り、空なら送らない。改行は不可（1行） |
| 連投制限 | 1人あたり **3秒で5件** まで。超えたら `{ error: '少し待ってから送ってください' }` |
| 安全 | メッセージは**必ずエスケープして表示**する（`textContent` か `esc()`）。HTMLとして解釈しない。URLのリンク化もしない |
| 観戦者の発言 | `spectatorSeesAll = true` かつ ゲーム中（playing）は、観戦者・脱落者の発言は **「観戦席」チャンネル** にだけ届く（プレイヤーには見えない）。ロビー・結果画面では全員に届く |
| 観戦席チャンネル | 観戦者・脱落者だけが読める。`spectatorSeesAll = false` のときは使わない（全員が同じチャット） |
| システムメッセージ | 入室・退室・ゲーム開始・ゲーム終了・ホスト交代をチャットに流す（灰色・小さめ） |
| ゲームからの通知 | 流さない（ログは各ゲームの `.log` に任せる。チャットが埋まるため） |

## 3. サーバー

### 3-1. データ
```
room.chat = [{ id, at, kind: 'user'|'reaction'|'system', channel: 'all'|'spectators',
               fromId, fromName, text }]   // 最新100件
member.chatTimes = number[]                // 連投制限用（直近の送信時刻）
```
- `id` は連番、`at` は `Date.now()`
- `fromName` は送った時点の名前を保存する（その後の退室に備える）

### 3-2. イベント
| イベント | 処理 |
|---|---|
| `chat:send` `{ text }` | 検証（2章）→ channel を決める（3-3）→ 保存して、そのメッセージを読める人に `chat:message` を送る |
| `chat:react` `{ key }` | `key` は 4章のリストにあるものだけ受け付ける。`kind:'reaction'`、`text` は定型文。channel の決め方は `chat:send` と同じ |
| `chat:message`（サーバー→クライアント） | 1件分 |
| `chat:history`（サーバー→クライアント） | 入室時と再接続時に、その人が読める分だけを送る |

### 3-3. channel の決め方
```
role = roleOf(...)  // 'player' | 'spectator' | 'out'
if (room.phase === 'playing' && room.settings.spectatorSeesAll && role !== 'player') channel = 'spectators'
else channel = 'all'
```
- 読める人：`all` は全員、`spectators` は role が `spectator` か `out` の人だけ
- ゲームが終わったあとも、`spectators` のメッセージはプレイヤーには送らない（履歴にも含めない）。種明かしは口頭か、結果画面でのやり取りで十分なため

### 3-4. システムメッセージ
基盤の該当箇所で `pushSystem(room, '○○さんが入室しました')` を呼ぶ：
- 入室（観戦で入ったときは「○○さんが観戦に来ました」）、退室、ゲーム開始（「第N戦 開始」）、ゲーム終了（「ゲーム終了」）、ホスト交代
- 切断・再接続は流さない（スマホのスリープでうるさくなるため）

## 4. クイックリアクション
定型文は基盤に固定で持つ（`lib/reactions.js`）。サーバーとクライアントで同じものを使う。
```
nice: 'ナイス！', hurry: 'はやく〜', think: 'うーん…', wow: 'すごい', sorry: 'ごめん',
lol: 'ｗｗｗ', gg: 'おつかれ！', again: 'もう1回！'
```
- 送られたリアクションは、チャットに1行で残るのに加えて、**送った人の席の上に吹き出しで2秒表示**する
  - 席の要素に `data-member-id="<id>"` を付けておけば、基盤がその上に吹き出しを重ねる。各ゲームの client.js は、席に `data-member-id` を付けるだけでよい
  - 席が見つからない（ロビーや、席を描かないゲーム）ときは、画面上部に小さなトーストで表示する
- `spectators` チャンネルのリアクションは、観戦者・脱落者にだけ表示する

## 5. 画面

### 5-1. 置き場所
| 画面幅 | ロビー | ゲーム |
|---|---|---|
| 1100px 以上 | 紙パネルの下にチャット欄（高さ 280px） | 右列を **「チャット」「ルール」のタブ** にする。初期表示はチャット |
| 768〜1099px | 同上 | 右列を同じくタブにする |
| 767px 以下 | 紙パネルの下にチャット欄（高さ 240px） | ゲームバーに「チャット」ボタン（未読数バッジ付き）。押すとボトムシートで開く（ルールと同じ仕組み）。シートの上部に「チャット｜ルール」のタブ |

- ゲームバーの「ルール」ボタン（スマホ）は「チャット」ボタンに統合する（シート内のタブで切り替え）

### 5-2. チャット欄の中身
- **メッセージ一覧**：
  - 自分の発言は右寄せ（紙色の吹き出し）、他人は左寄せ（名前を小さく上に添える）
  - システムメッセージは中央・灰色・小さめ
  - リアクションは、他人のものも1行で太字
  - 観戦席チャンネルのメッセージには「観戦席」の小さなタグを付け、背景を少し変える
  - 時刻は表示しない（読みやすさ優先）
  - 一番下までスクロールしているときだけ自動で追従する。上を読んでいる間に新着が来たら「新着メッセージ ↓」ボタンを出す
- **リアクション列**：8個の定型文を横スクロールのチップで並べる（タップで即送信）
- **入力欄**：`<input>`（140文字・Enterで送信）と「送信」ボタン
  - IME変換中のEnterで送信しないこと（`event.isComposing` を確認する）
  - 観戦席チャンネルに送られる状態のときは、入力欄のプレースホルダを「観戦席に送信（プレイヤーには見えません）」にする
- **未読**：チャットが閉じている・別タブを表示している間に届いた件数をバッジに出す（システムメッセージは数えない）
- **効果音**：他人のメッセージ・リアクションで `chat` 音（新規）。自分の発言とシステムメッセージでは鳴らさない。チャット専用のミュートは作らず、全体のミュートに従う
  - `sound.js` に `chat` を追加：sine 1318Hz を 40ms ＋ 1568Hz を 40ms、音量は控えめ（他の音の半分）

### 5-3. アクセシビリティ
- メッセージ一覧は `role="log"` と `aria-live="polite"`
- リアクションチップは `<button>`
- 入力欄には `<label>`（見た目は隠してよい）

## 6. テスト（test/room.flow.js にシナリオを追加）
1. ロビーで送ったメッセージが全員に届く。履歴は100件で古いものから消える
2. 141文字・空文字・空白だけ → 送れない
3. 3秒で6件目 → エラー
4. `<img src=x onerror=alert(1)>` を送る → そのままの文字列として保存・配信される（サーバー側は変換せず、表示側でエスケープする）。クライアントのテストは不要だが、表示コードで `innerHTML` に生の text を入れていないことをレビューで確認する
5. `spectatorSeesAll = true` のゲーム中：観戦者の発言は channel=spectators で、プレイヤーには `chat:message` が届かない。脱落者の発言も同じ
6. `spectatorSeesAll = false` のゲーム中：観戦者の発言は全員に届く
7. 再接続した人の `chat:history` に、その人が読めるものだけが入っている（プレイヤーには spectators のメッセージが入っていない）
8. 未定義の `chat:react` の key → エラー
9. 入室・退室・開始・終了・ホスト交代でシステムメッセージが流れる
