# 仕様 05：迷言メーカー（単語カードでフレーズを作るパーティーゲーム）＋ 基盤の「ゲーム設定」「タイマー」

ブランチ：`feature/meigen`
前提：CLAUDE.md、仕様01〜04（members / role / viewFor / spectatorView / readyCheck / チャット / 効果音 / ctx.prev）。
**最初に現状のコードを読み、名前が違う箇所は実際のコードに合わせること。読み替えた箇所は報告に書く。**

> 注意：これは市販ゲームの複製ではなく、オリジナルのゲームです。単語・お題・テーマはすべて `games/meigen/data/` の自作データだけを使うこと。市販ゲームのカード文言をネットから集めて足さないこと。

## 1. ルール
- 人数：**3〜8人**
- 毎ラウンド、1人が **親**（順番に交代。脱落はない）。親以外が **子**
- ラウンドの流れ
  1. **テーマ決め**：テーマの選び方（ゲーム設定）に従う。テーマの中からお題を1つランダムに出す（同じゲーム内で同じお題は出さない）
  2. **作成**：子は、手札の単語カードと、つなぎ言葉チップを並べてフレーズを作り、提出する。制限時間あり（ゲーム設定）
  3. **選考**：親は、誰が作ったか分からない状態で全員のフレーズを見て、一番気に入ったものを1つ選ぶ
  4. **発表**：作者を公開。選ばれた人に **+1点**
- 先に **目標点**（ゲーム設定、初期値5）に達した人の勝ち

### 手札
- **共通カード**：各自 **8枚**。ラウンドをまたいで持ち越す。使ったカードは捨て札になり、ラウンドの終わりに8枚まで補充する。山が尽きたら捨て札を混ぜ直す
- **テーマカード**：ラウンドごとに、そのラウンドのテーマの単語から各自 **4枚** を配る。ラウンドの終わりに回収する（同じラウンドで子同士が同じカードを持たないように配る）
- **つなぎ言葉チップ**：`common.json` の `connectors`。何度でも使える。手札ではない
- 親はそのラウンド、カードを使わない（親の共通カードも持ち越す）

### フレーズの条件
- トークン（カードかチップ）を **1〜10個** 並べる。**カードを最低1枚** 含む
- 表示するときはトークンを **区切りなしでつなげる**。テーマ単語の先頭にある「〜」は、表示のときに取り除く（例：「〜だった件」→「だった件」）

## 2. ゲーム設定（ロビーでホストが選ぶ）
| 設定 | 選択肢 | 初期値 |
|---|---|---|
| 目標点 | 3〜10（1刻み） | **5** |
| 作成の制限時間 | 30秒 / 60秒 / 90秒 / 制限なし | **60秒** |
| テーマの選び方 | 毎ラウンドランダム / 親が選ぶ / 固定 | **毎ラウンドランダム** |
| 固定テーマ | テーマ一覧から1つ（「固定」のときだけ表示） | 先頭のテーマ |

- **親が選ぶ**：ランダムな3候補から親が選ぶ。15秒以内に選ばなければランダムで決まる
- 毎ラウンドランダムのときは、直前のラウンドと同じテーマが続かないようにする

## 3. 基盤の追加（今後のゲームでも使う）

### 3-1. ゲーム設定（options）
- ゲームは `options` を宣言できる（任意）
  ```js
  options: [
    { key: 'target', label: '目標点', type: 'int', min: 3, max: 10, default: 5 },
    { key: 'timeLimit', label: '作成の制限時間', type: 'select',
      choices: [{ value: 30, label: '30秒' }, { value: 60, label: '60秒' }, { value: 90, label: '90秒' }, { value: 0, label: '制限なし' }], default: 60 },
    { key: 'themeMode', label: 'テーマの選び方', type: 'select', choices: [...], default: 'random' },
    { key: 'fixedTheme', label: '固定テーマ', type: 'select', choices: [...], default: 'hissatsu',
      showIf: { key: 'themeMode', equals: 'fixed' } }
  ]
  ```
  - `type`：`int`（min / max）・`select`（choices）・`bool`
  - `choices` は関数でもよい（テーマ一覧をデータから作るため）
- `room.options`：ゲームの default で初期化する。ホストが `lobby:option { key, value }` で変更する。サーバー側で型と範囲を検証し、違反なら `{ error }` を返す。変更したら、`lobby:settings` と同じく **全員の ready を外す**
- `setup(players, options)`：第2引数で渡す（既存ゲームは無視してよい）
- broadcast に `options`（現在値）と `optionDefs`（表示用。関数の choices は値に変換して送る）を入れる
- **ロビー画面**：ホストには、紙パネルの「ゲーム設定」欄に入力UI を出す（int は − / + ボタン付きの数値、select は `<select>`、bool はスイッチ）。ホスト以外には、現在の設定を読み取り専用で表示する（例：「目標 5点 ／ 制限 60秒 ／ テーマ 毎ラウンドランダム」）
- ゲームが終わってロビーに戻っても、設定は維持する

### 3-2. タイマー（締め切り）
ゲームが「時間切れ」を扱えるようにする。
- ゲームは `deadline(state)` → `number | null`（締め切りの時刻 ms。なければ null）を持てる
- ゲームは `onTimeout(state, room)` を持てる。締め切りを過ぎたときに基盤が呼ぶ
- 基盤は、broadcast のたびに `deadline` を見て、ルームごとにタイマーを1つだけ張り直す（`clearTimeout` → `setTimeout`）。発火したら `onTimeout` → `isOver` の確認 → broadcast
  - 発火時に `deadline(state)` がまだ未来なら（状態が変わっていたら）何もしない
- broadcast に `deadline` を入れる。クライアントは **サーバーとの時計のずれ** を補正して残り秒数を表示する（`room:update` に `serverNow: Date.now()` を入れ、受信時の `Date.now()` との差を `ctx.clockOffset` として渡す）
- 部屋が消える・ロビーに戻るときはタイマーを解除する
- 共通部品：`public/lib/timer.js` に `timerHTML(deadline, ctx)` と、表示を0.25秒ごとに更新する仕組み。残り10秒で赤く、残り5秒から毎秒 `tick` 音（新規：sine 880Hz 30ms、小さめ）

## 4. サーバー（games/meigen/server.js）

### メタ情報
```js
id: 'meigen', name: '迷言メーカー',
description: '手札の単語をつなげて、お題にぴったりの迷言を作ろう。親のハートをつかんだ人に1点！',
category: 'パーティー', cover: { color: '#8a4b2a', mark: '言', markColor: '#2a1a10' },
minPlayers: 3, maxPlayers: 8
```

### データの読み込み
- 起動時に `games/meigen/data/common.json` と `games/meigen/data/themes/*.json` を読み込む
- テーマのJSONの形式：`{ id, name, instruction, prompts: string[], words: string[] }`
  - 読み込み時に検証する（`id` がファイル名と一致・`prompts` が1件以上・`words` が子の人数×4枚＝32件以上）。不正なファイルはログを出して読み飛ばす
- カードは `{ id, text, kind: 'common'|'theme' }`。id は配るときに連番で振る（同じ単語が2枚あっても区別できるように）

### state
```
players, options, scores: number[], round, parent: 席,
phase: 'theme' | 'compose' | 'judge' | 'result' | 'over',
themeChoices: themeId[] | null, theme: themeId, prompt: string, usedPrompts: Set相当(配列),
hands: card[][] (共通), themeHands: card[][] (テーマ), commonDeck: card[], commonDiscard: card[],
drafts: (token[] | null)[],        // 作成中の下書き（時間切れ時に使う）
submissions: { seat, tokens, text }[], order: number[],  // order = 選考で見せる順（シャッフル）
pick: number | null,               // 選ばれた submissions の index
deadlineAt: number | null, winner: 席 | null, log
token = { t: 'card', id } | { t: 'chip', text }
```

### action
| type | 誰が・いつ | 処理 |
|---|---|---|
| `chooseTheme` `{ themeId }` | 親・phase=theme | 候補にあるものだけ。決まったら compose へ |
| `draft` `{ tokens }` | 子・compose | 下書きを保存する（検証はゆるく：自分のカード id とチップだけ残す）。broadcast しなくてよい（戻り値で `{ silent: true }` を返せる仕組みを基盤に足す） |
| `submit` `{ tokens }` | 子・compose・未提出 | 1章の条件で検証する。使ったカードを手札から抜き、提出する。子が全員提出したら judge へ |
| `unsubmit` | 子・compose・提出済み | 提出を取り消し、カードを手札に戻す |
| `pick` `{ index }` | 親・judge | 選んだ人に +1点 → result へ。目標点に達したら over |
| `next` | 誰でも・result | 準備OK（readyCheck）。全員そろったら次のラウンドへ |
| `forcePick` | ホスト・judge・親が切断中 | ランダムに選ぶ |

- 締め切り（`deadline` / `onTimeout`）
  - theme（親が選ぶモード）：15秒 → ランダムで決める
  - compose：設定の秒数（0なら締め切りなし）→ 未提出の子は、下書きが条件を満たせばそれで自動提出、満たさなければ「不参加」。提出が0件ならそのラウンドは流れる（親は交代し、点はなし）
  - judge・result：締め切りなし
- `turnOf`：theme では親、compose では未提出の子全員、judge では親、それ以外は `[]`
- `isOut`：常に false（脱落はない）。退席した人だけ true
- `onLeave`：その席を退席扱い。親が抜けたらラウンドを流して次の親へ。残りが2人以下になったら、その時点の最高点の人の勝ちで over

### view（★匿名性と手札を守る）
- 自分の共通手札・テーマ手札・下書き：本人だけ
- 他人の手札は **枚数だけ**
- compose 中の提出状況：**誰が提出済みか（true/false）だけ**。内容は送らない
- **judge 中：フレーズを `order` の順で送るが、作者（seat / id）は送らない**。自分の作品には `mine: true` を付ける（自分の作品が分かるのは本人だけ）
- result / over：作者を含めて全部
- spectatorView
  - seesAll=false：手札は枚数だけ。judge 中は匿名のフレーズだけ（作者なし）
  - seesAll=true：全員の手札と、作成中の下書きも見せる。judge 中の作者は **見せない**（観戦者がチャットでばらすのを防ぐため）

## 5. 画面（games/meigen/client.js / client.css）
卓上カフェの見た目に合わせる。単語カードは紙の短冊のような横長のカード（トランプとは別の部品。`.mg-word`）。

### 5-1. 共通
- 卓（.felt）の上部に **お題カード**：テーマ名（小さく）＋お題（大きく）＋説明文（「この商品のキャッチコピーを考えよう」など）。紙のカード風で少し傾ける
- 席：親には「親」バッジ、子には提出済み「✓」。点数を表示する
- 残り時間：`timerHTML`

### 5-2. テーマ決め（親が選ぶモード）
- 親：3つのテーマを大きなボタンで出す
- 子：「○○さんがテーマを選んでいます」

### 5-3. 作成（子）
- **作成中のフレーズ欄**（紙の帯）：並べたトークンを左から表示し、下に完成した文字列を大きくプレビューする
  - トークンをタップすると外れる
  - トークンを長押し（またはドラッグ）で並べ替える。難しければ、各トークンの左右に小さな「‹ ›」ボタンを付けて移動できればよい
- **テーマカード**（4枚・色違い）と **共通カード**（8枚）：タップでフレーズの末尾に追加。使ったカードは手札で薄く表示する
- **つなぎ言葉チップ**：横スクロールの小さなチップ列
- ボタン：「提出する」（primary・条件を満たさないと無効）、「全部外す」
- 提出後：「提出しました（みんなを待っています 3/5）」と「取り消す」
- 下書きは、変更から0.5秒後に `draft` を送る（まとめて送る）
- 親の画面：お題と「みんなが考えています（提出 2/5）」

### 5-4. 選考
- 全員に、フレーズの一覧を短冊として縦に並べる（作者は出さない）。自分の作品には小さく「あなた」
- 親：短冊をタップで選び、「これに決めた！」で確定する。選ぶまで何度でも変えられる
- 子：「親が選んでいます…」

### 5-5. 発表
- 選ばれた短冊を大きく表示し、作者名と「+1点」を出す。他の短冊にも作者名を表示する
- 準備OKの一覧とボタン（きゅうりと同じ部品）
- 決着したら勝者を大きく表示する

### 5-6. .g-side
- 点数表（目標点までのバー付き）、これまでの「選ばれた迷言」の一覧（ラウンド・お題・作者・フレーズ）、記録

### 5-7. ルール（export const rules）
1章を5〜7行の箇条書きにする。「つなぎ言葉は何回でも使える」「親は誰の作品か分からない」を必ず入れる。

### 5-8. 効果音
| 条件 | 音 |
|---|---|
| カードを置いた（自分の操作） | `card` |
| 誰かが提出した | `ready` |
| judge になった | `flip` |
| 選ばれたのが自分 | `win` |
| 選ばれたのが他人 | `trick` |
| over | `win` |
| 残り5秒から毎秒 | `tick`（基盤のタイマーが鳴らす） |

## 6. テスト
- `test/meigen.random.js`（npm test に追加）：3〜8人 × 各1000ゲームを、テーマ選択・下書き・提出・取り消し・時間切れ（締め切りを過去にして `onTimeout` を直接呼ぶ）・選考・準備OK・切断・退席の乱択で最後まで回す
- 毎ステップ検証すること
  - **judge 中、全員の view と spectatorView（seesAll の両方）に、作者を特定できる情報（seat・id・名前）が含まれない**
  - **compose 中、他人の view に自分の下書き・提出内容・手札の中身が含まれない**
  - 共通カードの総数（手札＋山＋捨て札＋提出中）が常に一定
  - 子同士でテーマカードが重複しない
  - 同じゲーム内で同じお題が出ない（お題が尽きた場合はリセットしてよい）
  - 点数は選ばれた回数と一致し、目標点に達した人がいれば over
- `test/room.flow.js` に追加：`lobby:option` の検証（範囲外はエラー・ホスト以外はエラー・変更で ready が外れる・ロビーに戻っても維持）、タイマー（`COUNTDOWN_MS` と同じく、テスト用に締め切りを短くできる環境変数 `MEIGEN_TIME_SCALE` などを用意してよい）
