# 仕様 10：喫茶店のレシピ帳（材料を集めてレシピを作り、常連さんを呼ぶボードゲーム）

ブランチ：`feature/recipe`
前提：CLAUDE.md、仕様01〜09（turnOf / ctx.prev / ctx.sound / .g-layout / rules / isOut・spectatorView / チャット / options / deadline・onTimeout / 乱数の注入 / #side-col）。
**最初に現状のコードを読み、名前が違う箇所は実際のコードに合わせること。読み替えた箇所は報告に書く。**

> カードデータ `games/recipe/data/cards.json` は渡されたものをそのまま使い、中身を変えないこと（バランス確認済み）。
> これは市販ゲームの複製ではなくオリジナルのゲーム。名前・絵・カード一覧は自分たちのもの。

## 1. 用語
| 用語 | 内容 |
|---|---|
| 材料 | コーヒー豆・ミルク・抹茶・いちご・はちみつ の5種類のチップ |
| 秘伝のスパイス | 万能チップ。どの材料の代わりにもなる。レシピを予約したときだけもらえる |
| レシピ | カード。段階は 1=まかない（40枚）2=定番（30枚）3=看板メニュー（20枚）。作るとそのカードの **割引（bonus）** が永久に1つ増え、点数があれば得点 |
| 割引 | 作ったレシピの bonus の数。その材料のコストが、その数だけ減る |
| 常連さん | 10人。必要な割引の組み合わせ（例：コーヒー4・ミルク4）がそろうと来店し、3点 |

## 2. ルール
### 準備
- 人数：**2〜4人**。手番の順はランダム
- 材料チップの数（各種類）：2人＝4枚、3人＝5枚、4人＝7枚。秘伝のスパイスは人数に関係なく5枚
- レシピの山を段階ごとにシャッフルし、各段階から4枚ずつ表向きに並べる（場）
- 常連さんを「人数＋1」人ランダムに選んで並べる

### 自分の番（次のどれか1つ）
1. **違う材料を3つ取る**（場にある種類のうち、違う3種類を1つずつ。残っている種類が3未満なら、残っている種類を1つずつでよい）
2. **同じ材料を2つ取る**（その材料が場に **4枚以上** 残っているときだけ）
3. **レシピを予約する**：場の表向きの1枚、または山の一番上の1枚（**見ずに取る**）を手元に置く。秘伝のスパイスが残っていれば1枚もらう。予約は **3枚まで**
4. **レシピを作る**：場の1枚か、自分の予約の1枚。コスト（割引を引いた分）を材料で払い、足りない分は秘伝のスパイスで払う。払ったチップは場に戻る。場から作ったら、同じ段階の山から1枚補充する（山が尽きたら空いたまま）

### 番の終わり
- 手元のチップ（スパイス込み）が **10枚を超えていたら**、10枚になるまで自分で選んで戻す
- 常連さんの条件を満たしていたら、その常連さんが来店する（3点）。**1回の番で来店するのは1人まで**。複数満たしていたら自分で選ぶ
- 何もできない（取れる材料がなく、予約も作るもできない）ときはパスになる

### 終了と勝敗
- 誰かが **15点以上**（ゲーム設定）になったら、その周の最後の人の番まで続けて終了（全員の番の数をそろえる）
- 点数が一番多い人の勝ち。同点なら **作ったレシピが少ない人** の勝ち。それも同じなら引き分け（同率で勝ち）
- 念のための打ち切り：100周で、その時点の点数で決める

## 3. ゲーム設定（options）
| key | 表示 | 選択肢 | 初期値 |
|---|---|---|---|
| `target` | 勝利点 | 10〜21 | **15** |
| `turnTime` | 1ターンの制限時間 | 30 / 60 / 90秒 / なし | **60秒** |

- 時間切れ：捨てるチップの選択中なら、一番多いチップから自動で戻す。常連さんの選択中なら最初の候補を選ぶ。それ以外なら **パス**

## 4. サーバー（games/recipe/server.js）

### メタ情報
```js
id: 'recipe', name: '喫茶店のレシピ帳',
description: '材料を集めてレシピを作り、割引を増やして看板メニューへ。常連さんにも来てもらおう！',
category: 'ボード', cover: { color: '#6b4226', mark: '珈', markColor: '#2a1a10' },
minPlayers: 2, maxPlayers: 4
```

### データの読み込みと検証
- 起動時に `data/cards.json` を読み込み、段階ごとの枚数（40/30/20）、常連さん10人、材料5種類を検証する

### state
```
players, options, order, turnIdx, round,
bank: { coffee, milk, matcha, berry, honey, spice },
decks: [card[], card[], card[]], market: [card[], card[], card[]],
regulars: regular[],
seats: [{ tokens: {...6種}, bonus: {...5種}, points, built: card[], reserved: [{ card, hidden: boolean }], regulars: regular[] }],
pending: null | { type: 'discard', over: n } | { type: 'regular', choices: regularId[] },
phase: 'play' | 'over', finalRound: boolean, winners: 席[],
last: { seq, seat, action, ... } | null,   // 演出用（何をしたか）
deadlineAt, log
```

### action
| type | 内容 |
|---|---|
| `take3` `{ colors: [..] }` | 違う材料を3つ（残り種類が少なければ少なくてよい） |
| `take2` `{ color }` | 同じ材料を2つ（場に4枚以上のときだけ） |
| `reserve` `{ tier, index }` | 場の1枚を予約。`index: 'deck'` なら山の一番上を見ずに予約 |
| `build` `{ from: 'market'|'reserved', tier?, index }` | 作る。支払いはサーバーで計算する（材料を先に使い、足りない分をスパイス） |
| `discard` `{ tokens: {color: n} }` | pending=discard のとき。ちょうど10枚になる分だけ |
| `chooseRegular` `{ id }` | pending=regular のとき |
| `pass` | 何もできないときだけ受け付ける |

- `pending` があるときは、その action しか受け付けない。`pending` が解消したら番を次へ進める
- `turnOf`：play 中は手番の人。`deadline` / `onTimeout`：3章
- `isOut`：退席した人
- `onLeave`：その人の予約カードは捨て、チップは場に戻す。手番中なら次へ。残りが1人なら over（残った人の勝ち）

### view（★隠し情報）
- **山から見ずに予約したカード（hidden: true）は、本人にだけ中身を送る**。他人には「段階」だけ（裏向きのカードとして表示する）
- 場から予約したカードは、全員に中身を見せてよい（みんなが見ていたカードのため）
- 山の中身・順番は誰にも送らない（残り枚数だけ）
- spectatorView：seesAll=false では hidden の予約を伏せる。seesAll=true では見せる
- 自分の番のとき、表示用に「各カードを作れるか」「作るときの支払い内訳」をサーバーで計算して付けてよい

## 5. 画面（games/recipe/client.js / client.css）

### 5-1. 場（.felt の中）
- 上から **常連さん** の列 → **看板メニュー（段階3）** → **定番（段階2）** → **まかない（段階1）** の行
- 各行の左端に **山**（裏向きのカード。段階の名前と残り枚数）。右に表向きの4枚
- 材料チップの **銀行**：5種類＋スパイスを丸いチップで並べ、残り数を表示する

### 5-2. カードの見た目（短い紙のカード、縦長）
- 上の帯：段階の色（まかない＝薄茶、定番＝深緑、看板＝えんじ）
- 左上：点数（0なら表示しない）、右上：bonus の材料アイコン
- 中央：レシピ名（小さめ、2行まで）
- 下：コスト（材料アイコン＋数の丸。0の材料は出さない）
- 自分の番で作れるカードは、ふちを金色にする

### 5-3. 材料アイコン
- 画像ファイルは使わず、インラインSVGの単純な形で描く：コーヒー豆（楕円＋中央の線）、ミルク（しずく）、抹茶（葉っぱ）、いちご（逆三角＋へた）、はちみつ（六角形）、スパイス（星）
- 色は `cards.json` の `ingredients[].color`。ミルクは白なので、細い濃い色の枠を付ける
- 色だけに頼らないよう、形でも区別できるようにする

### 5-4. 操作（自分の番）
- **材料を取る**：銀行のチップをタップして選ぶ（違う種類なら3つまで、同じ種類を2回タップで2つ）。選んだものが下の「取る」ボタンの横に並ぶ。条件を満たしたら「取る」が押せる。「選び直す」もある
- **カードをタップ**すると小さなパネルが出る：レシピ名・点数・bonus・コスト、**割引後に払う内訳**（スパイスを何枚使うか）、ボタン「作る」（作れるときだけ）「予約する」（3枚未満のとき）
- **山をタップ**すると「見ずに予約する」
- **10枚を超えたとき**：「チップを○枚戻してください」のパネルで、戻すチップを選んで確定
- **常連さんが複数**：選ぶパネルを出す
- 他人の番は見るだけ

### 5-5. プレイヤーの欄（.g-side）
各プレイヤーごとに：名前・点数（勝利点までのバー）・手元のチップ（種類ごとの数）・割引（種類ごとの数。材料アイコンに数字）・予約（自分は中身、他人は場から取った分は中身・山から取った分は裏向き）・来店した常連さん。手番の人を強調する。
- 自分の欄は一番上に、少し大きく表示する（スマホでは卓のすぐ下）
- 記録（.log）：「あき：コーヒー・抹茶・いちごを取った」「べん：『抹茶パフェ』を作った（+2点）」「しー：常連の『窓際の小説家』が来店（+3点）」

### 5-6. 演出と効果音
| 出来事 | 演出 | 音 |
|---|---|---|
| 材料を取る | チップが銀行からその人の欄へ動く（0.3秒） | `ready` |
| レシピを作る | カードが場からその人の欄へ動き、割引の数字が+1 | `trick` |
| 予約 | カードが裏返ってその人の欄へ | `card` |
| 常連さんの来店 | 常連さんのカードが光って移動、「+3」 | `win`（短め） |
| 最終周に入った | 「最終周です！」の帯を表示 | `turn` |
| 決着 | 勝者を大きく表示し、点数の一覧 | `win` |

`prefers-reduced-motion` のときは動きを省く。

### 5-7. ルール（export const rules）
2章を7〜9行の箇条書きにする。「同じ材料2つは4枚以上あるときだけ」「チップは10枚まで」「15点で最終周」を太字にする。

### 5-8. レイアウト
- PC：卓（場）を中央に大きく。プレイヤーの欄は .g-side
- スマホ（390px）：場のカードは5列（山＋4枚）で1枚あたり約64px幅。タップしやすさのため、カードをタップしたときのパネルを大きめにする。横スクロールは出さない

## 6. テスト（test/recipe.random.js を追加し、npm test に入れる）
2〜4人 × 各1000ゲームを、シード付きの乱数で、合法な手の中からランダム（＋ときどき「作れるなら作る」を優先）に選んで最後まで回す。毎ステップ検証すること：
- **チップの総数が常に一定**（銀行＋全員の手元＝初期値）
- 番の終わりに、全員の手元が10枚以下
- `take2` はその材料が4枚以上のときだけ成功。`take3` で同じ種類は拒否
- 支払いが正しい（割引→材料→スパイスの順。払いすぎない・足りないのに作れない）
- 予約は3枚まで。予約でスパイスが残っていれば1枚増える
- 常連さんは1回の番で1人まで、条件を満たしたときだけ来店し、同じ常連さんは二度来ない
- 15点到達後、その周の最後の人まで番が回ってから終わる（全員の番の数が同じ）
- 同点のときは作ったレシピが少ない人の勝ち
- **山から見ずに予約したカードの中身が、本人以外の view と seesAll=false の spectatorView に含まれない**
- 山の中身が誰の view にも含まれない
- 不正な action（他人の番・pending 中の別 action・コスト不足など）はすべて `{ error }`
